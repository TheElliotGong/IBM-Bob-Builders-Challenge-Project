# Bob Workflow Log — Satellite Launch Vehicle / Rideshare Configurator

This document records how IBM Bob was used as the primary development tool
throughout the IBM AI Builders Challenge project. It is committed to version
control as evidence of Bob's integration into the workflow.

---

## Tool

**IBM Bob** (AI SDLC partner, IDE edition)
Modes used: `agent`, `plan`, `ask`

---

## Phase 1 — Architecture & scoping

**Bob's role:** Translate the challenge brief into a concrete feature set and
technical plan.

- Reviewed the IBM AI Builders Challenge brief and Space Exploration track requirements.
- Proposed the **parse → filter → rank → explain** pipeline as the core architecture.
- Produced `launch-vehicle-configurator-plan.md` as a day-by-day build plan.
- Defined the six structured mission fields (payload mass, orbit type, target altitude,
  budget ceiling, max lead time, inclination flexibility) that drive all downstream logic.
- Designed the graceful-degradation strategy: every AI step has a deterministic fallback
  so the app works without a Gemini API key.

---

## Phase 2 — Core pipeline implementation

**Bob's role:** Generate and iterate on the business-logic modules.

| File | Bob's contribution |
|------|--------------------|
| `src/lib/types.ts` | Defined all shared TypeScript interfaces |
| `src/lib/parser.ts` | Gemini structured-output prompt + regex fallback |
| `src/lib/filter.ts` | Hard-constraint catalog filter |
| `src/lib/ranker.ts` | Weighted scorer with priority normalization |
| `src/lib/explainer.ts` | Gemini explanation prompt + template fallback |
| `src/lib/improver.ts` | Gemini description improver + plain-list fallback |
| `data/catalog.json` | Curated 7-vehicle catalog with all required fields |
| `data/catalog.schema.json` | JSON Schema (draft-07) for catalog validation |

---

## Phase 3 — API routes

**Bob's role:** Wire the pipeline into Next.js App Router route handlers.

- `src/app/api/parse/route.ts` — POST handler calling `parser.ts`
- `src/app/api/rank/route.ts` — POST handler calling `filter.ts` + `ranker.ts`
- `src/app/api/explain/route.ts` — POST handler calling `explainer.ts`
- `src/app/api/improve/route.ts` — POST handler calling `improver.ts`

All routes validated with Zod; error responses follow a consistent shape.

---

## Phase 4 — Test suite

**Bob's role:** Write the full Jest test suite from scratch.

73 tests across 5 modules, covering:
- Happy path (mocked Gemini responses)
- Fallback path (no API key / Gemini error)
- Edge cases (missing fields, out-of-range values, malformed input)

| Test file | Coverage target |
|-----------|----------------|
| `src/__tests__/parser.test.ts` | `parser.ts` — Gemini path + regex fallback |
| `src/__tests__/filter.test.ts` | `filter.ts` — all hard-constraint combinations |
| `src/__tests__/ranker.test.ts` | `ranker.ts` — priority weighting + tie-breaking |
| `src/__tests__/explainer.test.ts` | `explainer.ts` — Gemini path + template fallback |
| `src/__tests__/improver.test.ts` | `improver.ts` — Gemini path + list fallback |

## Phase 5 — UI implementation

**Bob's role:** Build and iterate on the single-page UI.

- Initial `src/app/page.tsx` scaffold with form, results panel, and weight sliders.
- `src/components/DownloadMenu.tsx` — JSON and Markdown export.
- `src/components/SessionHistoryPanel.tsx` — localStorage-backed session history.
- Post-parse confidence nudge — inline callout surfacing low-confidence fields after
  a parse, with a one-click link back to the improve panel.
- Layout and accessibility iterations based on conversational feedback.

## Commit convention

Commits where Bob generated or substantially modified the code are prefixed `[bob]`.
Example: `[bob] add weighted ranker with priority normalization`

This convention allows the git log to be filtered for Bob-driven changes:

```bash
git log --oneline --grep="\[bob\]"
```
